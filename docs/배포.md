## 다른 PC에서 수정하고 갱신하기

Node.js 22 이상에서 저장소를 clone하고 `npm ci --ignore-scripts`로 설치합니다. `npm test`, `npm run build:pages`, `node scripts/pages-check.mjs`로 확인한 후 main에 push하면 GitHub Actions가 자동으로 Pages를 갱신합니다.

`dist`는 자동 생성물입니다. 직접 수정하지 마세요. `public`과 게임 규칙을 수정합니다. Pages 빌드에서는 루트 경로를 상대 경로로 바꾸고 WebSocket 연결을 전용 Worker의 PracticeSession으로 교체합니다. 원래 Node 서버 모드는 그대로 유지합니다.

## 멀티플레이 서버 컨테이너

Docker를 지원하는 호스트에서는 `docker build -t rift-server .` 후 `docker run --rm -p 4175:4175 rift-server`로 실행합니다. 이 서버 주소에서 게임 화면과 WebSocket을 함께 제공합니다. HTTPS 역방향 프록시는 WebSocket 업그레이드와 원래 Host 헤더를 보존해야 합니다. /health를 상태 점검에 사용합니다.

기본 실행은 비관리자 node 사용자이며 개발 패키지·연구 자료·로그·인증 파일을 이미지에 넣지 않습니다. 참고: https://docs.docker.com/guides/nodejs/

방과 경기는 서버 메모리에 있으므로 현재는 단일 인스턴스로 실행합니다. 재시작 시 경기가 사라지며 여러 인스턴스 사이의 방 공유는 구현되지 않았습니다. 아직 외부 호스팅 서비스에 설치하거나 요금제를 만들지 않았습니다.

검증 하네스: `node scripts/remote-smoke.mjs http://127.0.0.1:4175`. HTTP 공개 파일, 비공개 파일 차단, 실제 소켓 두 개의 입장과 10인 경기 시작을 검사합니다. 자동 검증 서버에만 실행하세요. 임시 방을 생성합니다. `.github/workflows/server.yml`은 Linux 컨테이너 빌드/실행 후 이 검사를 수행합니다. 로컬 실제 소켓 검사는 통과했으며 Docker 자체 검증 결과는 GitHub Actions에서 확인합니다.

2026-10-16 Linux 컨테이너 검증 **통과**: https://github.com/lo4lolo/rift-protocol/actions/runs/38819132440 . 실제 이미지 빌드, 비관리자 컨테이너 실행, HTTP 검사, 두 WebSocket의 10인 경기 시작이 모두 성공했습니다. 외부 장기 호스팅이나 물리 PC 간 플레이 검증과는 구분합니다.
