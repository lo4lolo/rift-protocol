# 0.2 네트워크 구현과 검증

## 이동 예측

클라이언트는 30Hz로 입력 명령을 생성합니다. 명령 하나는 1/60초 물리 계산 두 번이며, 클라이언트가 보내는 시간 길이는 신뢰하지 않습니다. `netcode.mjs`의 같은 계산을 서버와 화면 예측이 사용합니다.

서버는 받은 seq와 처리 완료 ack를 구분하고, 시간당 허용된 수만 처리합니다. 최대 12개 명령을 대기시킵니다. 라운드 번호가 다르거나 seq가 뒤로 가거나 잘못된 숫자가 들어오면 거부합니다. 입력을 중단해도 공중에 멈출 수 없도록 중력은 계속 적용합니다.

화면은 서버 상태와 ack를 받으면 처리된 명령을 버리고, 미처리 명령만 다시 계산합니다. 작은 시각 오차는 카메라 오프셋으로 부드럽게 줄이고 큰 이동/리스폰은 즉시 맞춥니다. 렌더 프레임의 남은 시간은 위치를 잠시 외삽할 뿐 서버 상태를 바꾸지 않습니다.

## 원격 플레이어

서버 스냅샷은 20Hz입니다. 클라이언트는 최대 20개를 보관하고 추정 서버 시각에서 100ms 이전의 두 상태 사이를 보간합니다. yaw의 양/음 회전 경계는 최단 회전으로 연결합니다. 큰 순간 이동, 사망, 새 라운드에서는 이전 위치를 길게 가로지르지 않습니다.

## 사격 지연 보정

클라이언트는 실제로 표시 중인 시각을 입력에 함께 보냅니다. 서버는 요청 시각을 최대 250ms 과거~현재 범위로 제한하고, 상대의 저장된 위치·높이·앉기 상태를 보간하여 히트박스를 검사합니다. 현재 사망한 상대나 이전 라운드의 기록에는 피해를 적용하지 않습니다. 발사 속도, 탄약, 벽, 피해량은 계속 서버가 결정합니다.

이 구현은 제한된 서버 rewind입니다. 각 접속의 신뢰 가능한 RTT를 기반으로 과거 범위를 더 좁히는 방어, 동적 장애물, 투사체 rewind, 고급 경쟁용 lag compensation은 아직 구현하지 않았습니다. 모든 적 좌표를 클라이언트에 전달하므로 서버 판정만으로 월핵까지 방지한다고 주장하지 않습니다.

## 지연 하네스

`scripts/latency-proxy.mjs`는 **검증 전용** HTTP/WebSocket 중계기입니다. 상행/하행 각각 100ms와 0~20ms 지터를 실제 메시지에 적용하고 WebSocket 순서는 보존합니다. 운영 서버에 디버그 경로나 지연 설정을 설치하지 않습니다.

검증 결과:

- 순수 시뮬레이션: 왕복 200ms와 순서 보존 지터에서 클라이언트 예측과 입력 기준 경로의 오차 0.025m 미만, 입력 소진 후 서버 위치에 수렴.
- 입력 폭주: 초당 수천 개 명령을 시도해도 이동량이 서버 시간에 해당하는 5.6m/s를 넘지 않음.
- 이동 표적: 현재 위치에서는 빗나가는 사격이 표시 시각의 과거 위치를 조준하면 피격. 과거 조회 범위와 라운드 경계 확인.
- 실제 Edge 2개: 지연 조건에서 이동·발사·재장전·능력·설정 저장.
- 실제 조준: UI 구매, X 드롭/E 회수, 권총 헤드샷 100→22, 후속 사격 처치, 두 화면의 승패 일치.

하네스는 모든 실제 인터넷 조건을 대신하지 않습니다. 무선 간섭·패킷 손실에 따른 TCP 정체·장시간 연결·물리 PC별 마우스 감각은 별도 검증 대상입니다.

## 0.9 복귀 세션

welcome에서 본인에게만 무작위 복귀 토큰과 마지막 seq를 전달합니다. 서버는 토큰→방/플레이어/현재 소켓을 메모리에 보관합니다. 연결 종료 시 입력을 지우고 30초간 자리를 유지합니다. 복귀는 같은 방의 끊긴 세션만 허용하며 활성 연결 중복은 거부합니다. 만료되면 플레이어와 불필요한 방을 정리합니다.

클라이언트는 토큰을 탭 sessionStorage에 보관하고 30초간 2초마다 재시도합니다. 원래 seq 이후부터 입력을 보내며 예측/스냅샷 버퍼는 다시 시작합니다. 서버 재시작이나 다른 PC로의 상태 이전은 지원하지 않습니다. 공개 계정 인증이나 장기 세션 보안 체계가 아닙니다.

소켓 10개 × 8회 복귀 하네스 통과. 브라우저 재시도/화면은 사용자 마우스 방해 금지 요청으로 미검증입니다.
